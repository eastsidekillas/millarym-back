# Выгрузка «Для номенклатурного плана»

## Зачем

Каждую неделю менеджеры выгружают изделия своих партнёров, которых пора отгружать, и отправляют файлы руководителю. Руководитель сводит их в общий номенклатурный план, распределяет по дням и бригадам и постоянно его перекраивает: изделия идут из работы сразу в машину, а люди болеют.

Выгрузка нужна, чтобы данные из CRM сразу ложились в колонки плана: файлы всех менеджеров одинаковые, их можно копировать в «котёл» без перестановки столбцов.

## Цели

- Менеджер отмечает галочками партнёров и получает xlsx с колонками строго в порядке плана.
- В файле есть всё, что уже хранит CRM, каждое значение в своей колонке.
- Файл вставляется в план без правок: без логотипа, заголовка и строк-групп, таблица начинается с первой строки.

## Не делаем

- Не храним в CRM цену (меняется, ведётся в 1С), дату отгрузки, пометку «ВАЖНО» и бригаду по плану. Эти колонки в файле есть, но пустые: их заполняет руководитель в Excel.
- Колонки не настраиваются менеджером. Если файлы начнут расходиться по составу колонок, цель провалена.
- Сводок по бригадам и дням («Кол-во по бригадам», «Даты отгрузки») нет: они остаются в Excel.

## Варианты (выбран А)

- **А. Отдельная выгрузка с фиксированными колонками.** Выбрана: одинаковые файлы, мало работы. Если руководитель перестроит план, порядок колонок меняют в коде.
- Б. Та же выгрузка, но колонки включает и выключает менеджер. Отклонено: файлы разных менеджеров разойдутся.
- В. Общий конфигуратор колонок для всех отчётов с сохранёнными наборами. Отклонено: втрое больше работы ради одного набора.

## Колонки (по порядку)

| Колонка | Откуда |
|---|---|
| ID | номер изделия |
| Заказ | номер заказа из старого номера (`114542 · 9578/ЗАК` → `9578`); у новых изделий пусто |
| Наименование изделия | название изделия (модель или название вне справочника) |
| Цена | пусто |
| Угол | из «Комплектации»: «Левый» / «Правый» |
| Накладки | из «Комплектации»: «венге» / «белые» / «серые» |
| Дополнение | «в шитье ДД.ММ.» / «отшит ДД.ММ.» (как в колонке «Отшит / в шитье») и остаток текста «Комплектации», который не попал в Угол и Накладки |
| Резерв | резерв |
| Менеджер | фамилия того, кто завёл изделие (`Item.manager`) |
| Склад | этап по названиям CRM: Заказы, Крой, Склад чехлов, В работе, СГП |
| ВАЖНО | пусто |
| Дата отгр. | пусто |
| Бригада | пусто |

## Выбор партнёров

- Параметр отчёта: список партнёров, отмечаются галочками. Партнёр — точное значение поля «Резерв» среди изделий не в Корзине; рядом количество изделий. Устроено как выбор моделей в «Свободных остатках» (отдельный эндпоинт со списком и счётчиками).
- В выгрузку попадают изделия всех этапов, кроме Корзины.
- Сортировка: по партнёру, внутри — по названию, одинаковые — по номеру (`by_reserve_then_title`).

## Экран и файл

- На экране отчёт показывается как остальные, с теми же колонками.
- xlsx для этого отчёта простой: первая строка — заголовки, дальше строки изделий. Без логотипа, заголовка, подзаголовка, групп и фото. Остальные отчёты оформляются как раньше.
- Имя файла: `Номенклатура <фамилия менеджера> <дата>`.

## Решения, принятые без руководителя (проверить)

- Тканей в выгрузке нет: в плане колонка «Угол/ткани/накладки», но ткани там не заполнены.
- «Менеджер» — тот, кто завёл изделие в CRM.
- «Склад» — названия этапов CRM, а не старые «Чехлы» / «В_работе».
- Список партнёров общий для всех, а не только партнёры текущего менеджера.
